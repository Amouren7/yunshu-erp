# 07 部署与运维

- 文档版本：v1.0
- 编写日期：**2026-10-23**
- 适用代码：`erp-suite@1.0.0`（2026-10-23 12:15 快照）
- 面向对象：实施/运维/测试人员，以及需要在本地跑起来的所有人
- 调试开发与发布验收请看 `scripts/e2e.mjs`（`npm run e2e`，67 项接口断言）、`scripts/audit.mjs`（全站 73 页巡检）与 `scripts/ui-flow.mjs`（16 项 UI 流程）。

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11、Linux、macOS | 本项目在 **Windows 11 x64** 验证 |
| Node.js | **≥ 22.5**（推荐 22 LTS / 24 LTS） | 必须内置 `node:sqlite`；本项目实测 **v23.9.0**。Node 22.5~23.x 会打印 `SQLite is an experimental feature` 警告，**属正常现象，不影响运行** |
| npm | ≥ 10（随 Node 附带） | 用于安装前端依赖 |
| 浏览器 | Chrome / Edge 最新版 | 打印、图表、截图脚本均以 Chromium 内核验证 |
| 内存/磁盘 | 内存 ≥ 2 GB；磁盘 ≥ 500 MB | `node_modules` 约 300 MB，数据库约 3~5 MB（含 WAL） |
| 端口 | **8787**（API + 前端）、**5173**（仅开发模式） | 均绑定 `127.0.0.1`，默认仅本机访问 |

> 不支持 Node < 22.5：`node:sqlite` 不存在，启动即报 `Cannot find module 'node:sqlite'`。

## 2. 安装

```powershell
# 1) 进入项目目录
cd "<项目根目录>\erp-suite"

# 2) 安装依赖（首次约 10~30 秒）
npm install
```

- 内网/镜像加速（可选）：
  ```powershell
  npm config set registry https://registry.npmmirror.com
  npm install
  ```
- 依赖只有 6 个运行时包（react/react-dom/react-router-dom/antd/@ant-design/icons/echarts/dayjs）+ 构建工具，**无需要编译的原生模块**（`node:sqlite` 由 Node 内置）。
- 验证 Node 具备 SQLite：
  ```powershell
  node -e "const {DatabaseSync}=require('node:sqlite');console.log('node:sqlite OK')"
  ```

## 4. 构建前端

```powershell
npm run build
```

- Vite 以 `web/` 为根目录构建，产物输出到 **`web/dist/`**（`server/index.mjs` 从这里托管静态资源）。
- 构建成功后会生成 `web/dist/index.html` 与 `web/dist/assets/*`；失败时检查 Node 版本与 `npm install` 是否完整。
- 修改前端代码后必须重新 `npm run build` 才会影响 `npm start` 的生产访问（开发模式用 `npm run dev` 不需要构建）。


```powershell
npm run dev       # 同时启动 API(8787) 与 Vite(5173)
```

| 服务 | 地址 | 说明 |
|---|---|---|
| 前端（Vite HMR） | http://127.0.0.1:5173 | 改 `web/src` 立即热更新 |
| 后端 API | http://127.0.0.1:8787 | Vite 已配置 `/api` 代理到该端口 |

- 开发模式访问 **5173**，API 请求由 Vite 代理，不需要 `npm run build`。
- Ctrl+C 同时结束两个子进程（`scripts/dev.mjs` 会回收）。

### 5.4 端口与环境变量

```powershell
# 换端口启动（API 与静态页面一起换）
$env:ERP_PORT = "9000"; npm start
# 换数据目录（例如把演示库放到别处）
$env:ERP_DATA_DIR = "D:\erp-data"; npm start
```

| 变量 | 默认值 | 作用 |
|---|---|---|
| `ERP_PORT` | `8787` | HTTP 服务端口 |
| `ERP_DATA_DIR` | `server/data` | SQLite 数据库目录（自动创建） |
| `ERP_BASE` | `http://127.0.0.1:8787` | 截图脚本目标地址（`npm run shots`） |
| `CHROME_PATH` | 自动探测 | 截图脚本使用的 Chrome/Edge 路径 |

> 注意：服务监听地址在 `server/index.mjs` 中硬编码为 `127.0.0.1`。**只能本机访问**；如需局域网访问，把它改为 `0.0.0.0` 并配置防火墙（见 §11）。

## 7. 数据备份、恢复与重置

### 7.1 关键事实：WAL 模式

数据库运行在 **WAL 模式**，`server/data/` 下同时存在：

```
erp.db        主库
erp.db-wal    预写日志（未合并的最新事务在这里）
erp.db-shm    共享内存索引
```

**热备份时三件必须一起复制**，否则可能丢最近事务或损坏。

### 7.2 在线备份（推荐，不停服）

SQLite 支持一致性快照导出。在项目目录执行：

```powershell
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('server/data/erp.db');db.exec(\"VACUUM INTO 'server/data/backup/erp-$(Get-Date -Format yyyyMMdd-HHmmss).db'\");db.close();console.log('backup ok')"
```

> 若在 PowerShell 中引号转义麻烦，可先建目录：`New-Item -ItemType Directory -Force server\data\backup`，再把命令放进 `.ps1` 执行。`VACUUM INTO` 生成的文件**已合并 WAL**，可直接复制离开。

### 7.3 停服冷备份（最稳）

```powershell
# 1) 停止服务（Ctrl+C 结束 npm start）
# 2) 打包备份（三件一起）
$ts = Get-Date -Format "yyyyMMdd-HHmmss"
New-Item -ItemType Directory -Force "D:\erp-backup" | Out-Null
Copy-Item "server\data\erp.db*" "D:\erp-backup\" -Force
Get-ChildItem "D:\erp-backup" | Rename-Item -NewName { "erp-$ts" + ($_.Name -replace '^erp\.db','') } -PassThru
```

### 7.4 恢复

```powershell
# 1) 停止服务
# 2) 清空当前数据目录（先确认备份可用！）
Remove-Item "server\data\erp.db*" -Force
# 3) 把备份的 erp.db（若冷备则连 -wal/-shm）复制回 server\data\
Copy-Item "D:\erp-backup\erp-20261023-120000.db" "server\data\erp.db"
# 4) 启动并校验
npm start
npm run check
```

`npm run check` 应输出：`负库存条数: { c: 0 }`、`借贷不平凭证: { c: 0 }`、总账借贷相等。

### 7.5 重置演示数据

| 方式 | 命令 | 说明 |
|---|---|---|
| 推荐 | `npm run seed` | 会清空全部表并重建（seed 开头即全表 DELETE），无需删库文件 |
| 重置脚本 | `npm run reset` | 删除 `server/data/erp.db*` 后重新生成；执行前必须停止服务 |
| 彻底重来 | 停服 → `Remove-Item server\data -Recurse -Force` → `npm run seed` | 连备份/临时文件一起清掉 |

> 重置会**丢失手工录入的所有数据**，仅用于演示环境。生产数据请先备份。

## 8. 升级与迁移

```powershell
# 1) 停止服务并备份数据
# 2) 更新代码（覆盖 server/ web/ scripts/ package.json 等）
npm install          # 依赖有变化时
npm run build        # 前端重新构建
npm run seed         # 仅演示环境：重建数据；生产环境跳过
npm start
```

- 表结构升级：`server/db.mjs` 的 `migrate()` 只在 `PRAGMA user_version < 1` 时执行 `schema.sql`；**已存在的库不会自动加表/加列**。升级若含 DDL 变更，需要手工执行 `ALTER/CREATE` 或把 `user_version` 递增并在 `migrate()` 中补迁移分支。
- 数据目录与代码解耦：把 `ERP_DATA_DIR` 指向独立目录，可在升级/替换代码时保留数据。

## 10. 生产部署建议（可选）

本项目定位是**单机演示/小型内部使用**，若要在小团队内正式使用，建议：

1. **改监听地址**：`server/index.mjs` 中 `server.listen(PORT, '127.0.0.1', ...)` → `'0.0.0.0'`，并仅在内网网卡暴露。
2. **反向代理 + HTTPS**（nginx 示例）：

```nginx
server {
  listen 443 ssl;
  server_name erp.example.com;
  ssl_certificate     /etc/ssl/erp.crt;
  ssl_certificate_key /etc/ssl/erp.key;

  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
  }
}
```

3. **进程守护**：Windows 用 [NSSM](https://nssm.cc/) 注册 `node server/index.mjs` 为服务；Linux 用 systemd `ExecStart=/usr/bin/node /opt/erp/server/index.mjs`，`Restart=always`。
4. **安全基线**：
   - 修改 `admin` 默认密码（用户管理 → 重置密码），或删除 `guest`；
   - 不要将 8787 直接暴露到公网；
   - 生产数据与演示库分离（`ERP_DATA_DIR` 指向独立目录 + 定期备份）；
   - token 存于 `localStorage`，高安全场景可改为 HttpOnly Cookie（需改 `api/client.ts` 与 `auth.mjs`）。
5. **备份策略**：每日 `VACUUM INTO` 备份并异地保存，保留 ≥ 14 天。

## 11. 常见问题排查（FAQ）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | 启动报 `Cannot find module 'node:sqlite'` | Node < 22.5 | 升级 Node（推荐 22 LTS 或 24 LTS），重开终端 |
| 2 | 控制台反复出现 `SQLite is an experimental feature` | Node 22/23 的 `node:sqlite` 仍标记实验特性 | 正常警告，可忽略；Node 24+ 逐步稳定 |
| 3 | 启动报 `EADDRINUSE` | 8787 被占用（旧的 `npm start` 未退出） | `netstat -ano | findstr :8787` 找到 PID → 结束进程；或 `$env:ERP_PORT="9000"; npm start` |
| 4 | 页面空白 / 404 / "前端尚未构建" | `web/dist` 缺失或未构建 | `npm run build` 后重启 `npm start` |
| 5 | 登录后立刻被踢回登录页 | token 过期（7 天）或数据库被重置 | 重新登录；浏览器控制台执行 `localStorage.removeItem('erp_token')` 后刷新 |
| 6 | 页面提示 `登录已过期` / 接口 401 | 服务重启后 `sessions` 表被清空过，或 token 无效 | 重新登录 |
| 7 | 数据为空 / 列表全空 | 未执行 seed，或误删数据库 | `npm run seed` 重建演示数据 |
| 8 | 执行 seed 报数据库被占用 / `SQLITE_BUSY` | 服务未停止，seed 与运行时同时写库 | 先 Ctrl+C 停止服务，再 `npm run seed` |
| 9 | `npm run reset` 报错 / 重置失败 | 服务未停止导致数据库被占用（脚本本身已修复） | 先停止服务再执行；或等价命令：停服 → `Remove-Item server\data\erp.db*` → `npm run seed` |
| 10 | `npm test` 失败 | `test` 实际执行 `scripts/e2e.mjs`（需要 Node 内置 fetch 与可用端口，会启动隔离服务） | 单独运行 `npm run e2e` 查看失败项；或改用 `npm run check`（数据自检） |
| 11 | 审核单据后提示「当前状态「DRAFT」不允许执行「审核」」 | 单据需先「提交」再「审核」（两步状态机） | 先点「提交」，刷新后再「审核」 |
| 12 | 审核单据后提示「库存不足」/ 库存为负 | 系统参数「允许负库存」关闭时会强制校验可用库存（默认演示环境为开启） | 先做采购入库/其他入库补库存，或在「系统管理 → 参数设置」开启「允许负库存」 |
| 13 | 打印页面空白/样式错乱 | 浏览器缩放或未启用"背景图形" | 打印预览中勾选「背景图形」，边距选「默认」；仅 `#print-area` 会被打印 |
| 14 | 图表不显示 | 容器宽度为 0（隐藏 tab 中初始化）或 echarts 未加载 | 刷新页面；确认 `npm install` 完整 |
| 15 | 导入/保存大单据报 413 | 请求体超过 20 MB | 拆分单据或调整 `http.mjs` 的 `readBody` 上限 |
| 16 | 日期差一天 / 时间不对 | 服务器时区与浏览器不一致；数据用 `datetime('now','localtime')` | 统一机器时区为 Asia/Shanghai |
| 17 | `npm run dev` 只出来一个服务 | 子进程启动失败（端口占用/依赖缺失） | 看终端红字；先停掉已有服务，或单独 `npm start` + `npx vite` |
| 18 | 截图脚本失败（`npm run shots`） | 未装 Chrome/Edge 或路径不识别 | 设置 `$env:CHROME_PATH="C:\...\chrome.exe"`；确保服务已启动 |
| 19 | 双击 `启动ERP.cmd` 窗口一闪而过 | 旧版脚本为 LF 换行，`cmd.exe` 解析错乱后立即退出；或 Node 不在 PATH | 已修复：`npm run launcher` 重新生成（CRLF）、`npm run verify:launcher` 自检；仍不行则命令行 `npm run boot` 查看报错 |
| 20 | 双击后提示「检测到云枢ERP已在运行」 | 服务已在 8787 监听（重复双击属正常） | 无需处理：浏览器会自动打开，直接使用；本窗口按任意键关闭 |
