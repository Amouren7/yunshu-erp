### 1.2 单据通用规则

1. **单据 = documents 一行 + document_lines N 行**，`doc_type` 决定字段与状态机；不允许每种单据建一张表。
2. **状态只能通过 `/api/documents/:id/action` 变更**，不在 PUT 里改 status。
3. **过账只在 `approve` 动作中发生**（事务内）：`status=APPROVED` → 写库存 → 写凭证 → 回写来源行数量 → 写日志。
4. **金额计算只走 `docService.lineCalc/docTotals`**，四舍五入 2 位；禁止前端算完传总额（前端算的只做展示）。
5. **权限命名**：`${module}.${action}`，action ∈ `view/create/edit/delete/submit/approve/export`；模块 key 必须与 `meta.mjs` 的 `MODULES` 一致（dashboard/basedata/sales/purchase/inventory/production/finance/hr/crm/reports/system）。
6. **每个写操作都要 `audit()`**；每个状态变化都要 `document_logs`。
7. **冻结枚举值**：状态值一旦写进种子数据与前端筛选器，只增不改（改名要迁移数据）。

### 1.3 金额/税额口径（与现有实现一致）

```
行未税金额 amount    = round2(qty × price × (1 − discount_rate/100))
行税额 tax_amount    = round2(amount × tax_rate/100)
行价税合计 total_amount = round2(amount + tax_amount)
表头 subtotal = Σ行 amount；tax_amount = Σ行 tax；total_amount = subtotal + tax_amount
出库成本 cost_amount = Σ行(qty × 出库时点 avg_cost)
```

### 2.3 状态迁移表（已有单据，全部冻结）

```text
SO:  DRAFT --submit--> SUBMITTED --approve--> APPROVED
     APPROVED --(DN 首次部分发货，系统)--> PARTIAL_SHIPPED
     APPROVED|PARTIAL_SHIPPED --(DN 发齐，系统)--> FULL_SHIPPED
     FULL_SHIPPED --(开票齐+收款齐，系统)--> COMPLETED
     APPROVED|PARTIAL_SHIPPED|FULL_SHIPPED --close(approve 权限)--> CLOSED
     DRAFT|SUBMITTED --void--> VOID
PO:  DRAFT --submit--> SUBMITTED --approve--> APPROVED
     APPROVED --(GRN 部分到货，系统)--> PARTIAL_RECEIVED
     APPROVED|PARTIAL_RECEIVED --(GRN 到齐，系统)--> FULL_RECEIVED
     FULL_RECEIVED --(AP 发票齐，系统)--> COMPLETED
     APPROVED|PARTIAL_RECEIVED|FULL_RECEIVED --close--> CLOSED
     DRAFT|SUBMITTED --void--> VOID
DN/GRN/SR/PR/TR/ADJ/OI/OO/RC/PY:
     DRAFT --submit--> SUBMITTED --approve--> APPROVED
     DRAFT|SUBMITTED --void--> VOID
     APPROVED --(仅当无下游/未生成凭证，且为当日)--> VOID（红冲，P1）
```

新增单据建议迁移：

```text
QUO: DRAFT --submit--> OPEN --(转 SO)--> ORDERED / PARTIALLY_ORDERED
     OPEN --(客户回复)--> REPLIED；OPEN|REPLIED --lose--> LOST；OPEN --expire--> EXPIRED
PRQ: DRAFT --submit--> SUBMITTED --approve--> APPROVED --(转 PO)--> ORDERED --(全部入库)--> CLOSED
     SUBMITTED --reject--> REJECTED
MI/FG: DRAFT --submit--> SUBMITTED --approve--> APPROVED（过账）
```

## 8. 风险与裁剪建议

| 风险 | 影响 | 处置 |
|---|---|---|
| 状态自动推进与人工操作并发 | 父单状态被覆盖 | 所有状态更新走 `UPDATE ... WHERE status=?`（乐观锁），冲突重试 |
| 事务边界不完整 | 库存变了、凭证没生成 | `applyEffect` 必须整体放在 `BEGIN/COMMIT`，失败回滚 |
| 浮点误差累积 | 报表差 0.01~1 元 | 金额一律 `round2`；汇总用 SQL `ROUND(SUM(...),2)`；对账容差 1 元 |
| 种子状态配比实现成本 | 工期被拖长 | S0 先做"每状态至少 1 条"的最低版本，S5 再扩容 |
| 前端单据页重复开发 | 12 种单据写 12 套页面 | 用 DocList/DocForm/DocDetail 驱动，新单据只写配置 |
| P2 功能诱惑 | 范围失控 | P2 一律不排期（本清单 §2.2 已标 P2）；只保留 DDL 注释 |
| 财务复杂度被低估 | 报表对不上 | 先做"凭证→余额表→利润表/资产负债表"直线链路，现金流量表 P1 后置 |

## 9. 给 Lead 的 10 条模块设计建议（浓缩版）

1. **单据一律走 `documents` 引擎**，新增 4 种（QUO/PRQ/MI/FG）也只加注册项，不新建表。
2. **状态值冻结**：SO 8 态、PO 8 态、其余 4 态；自动推进只改父单，不允许前端直接设状态。
3. **过账只在 approve 的事务里做**，先写 `vouchers` 幂等键，再写库存，失败整体回滚。
4. **库存三不变量**：只能由单据变动、台账只增不改、出库成本取过账时点均价。
5. **金额只有一处计算**（`docService.docTotals`），前端只展示；税按行算再汇总。
6. **信用/库存/超发/重复过账四道校验**放在 approve 前，错误码固定（前端好提示）。
7. **前端先写 4 个共享组件**（DocList/DocForm/DocDetail/ActionBar），12 种单据复用。
8. **补 `document_logs`**：任何状态变化必写，详情页时间线依赖它，也是审计要求。
9. **种子数据是功能的一部分**：每状态至少 1 条 + 12 个月连续 + 主数据 60/30/120，否则演示不成立。
10. **先闭环后完整**：S1 只做"销售到收款"一条贯通链路（含凭证），跑通后再复制到采购/库存/生产，避免四面开花。
