- **目标（Task）**：用一套可维护的架构，把销售到收款、采购到付款、生产到入库的链路跑通，并保证账实一致；独立完成需求分析、数据模型、后端、前端、测试与文档。

  1. 抽象 `documents + document_lines + document_logs` 三表，集中定义 12 种单据的字段、状态机、动作与转单规则。
  2. 将过账逻辑收敛到 `posting.mjs`，审核时在同一事务内写库存台账、发票、凭证并回写来源单，失败整体回滚。

## 4. 面试怎么讲（高频 15 问）

### 4.1 架构与选型

**Q1：为什么用 SQLite，而不是 MySQL/PostgreSQL？**
A：这是单机演示与内部试点，SQLite 零运维、单文件、事务完整，足够支撑 12 个月模拟数据和几十个并发读。局限是单写者，高并发写入会锁；如果做多人 SaaS，第一步就是把数据层换成 PostgreSQL，SQL 层已经参数化，迁移成本主要在连接池与并发控制。

**Q2：为什么所有单据共用三张表，而不是每种单据一张表？**
A：ERP 的单据结构高度相似（头、行、状态、来源、审批日志），共用表让转单、查询、权限、审计只需实现一次；差异通过 `docTypes.mjs` 的元数据描述。代价是单表行数增长和字段稀疏，靠索引与分页解决。

**Q3：新增一种单据要改哪些地方？**
A：在 `docTypes.mjs` 注册类型、字段、状态与动作，配置编号规则和过账效果，前端路由与菜单自动出现，不需要建表或写新表单。

### 4.2 业务与数据一致性

**Q4：审核时怎么保证库存、发票、凭证同时成功或同时失败？**
A：审核动作包在 `tx()` 里，事务内依次执行库存变动、发票生成、凭证写入、来源单回写；任一步抛错整体回滚。凭证本身还有借贷平衡校验，容差 0.01。

**Q5：移动加权平均成本具体怎么算？**
A：入库时新均价 =（原库存金额 + 入库金额）÷（原数量 + 入库数量），出库按出库时点的均价计价并写台账；台账只增不改，余额表由台账汇总校验。

**Q6：一张销售发货单审核后，账上发生了什么？**
A：库存减少并结转销售成本，确认收入和销项税，生成应收发票，生成凭证（借应收账款，贷主营业务收入与应交税费，同时借主营业务成本、贷库存商品），并回写销售订单已发数量与状态。

**Q7：怎么保证报表和总账一致？**
A：报表直接查凭证与余额表，不维护第二套数字；`check` 脚本校验总账借贷相等、资产等于负债加权益、负库存为 0。

**Q8：作废和红冲怎么处理？**
A：草稿可删除；已审核单据走作废动作，不物理删除；当前版本没有独立红冲按钮，需要做反向分录。这是已知限制，写在验收报告里。

### 4.3 权限与安全

**Q9：权限模型怎么设计？**
A：角色持有 `module.action` 权限码，支持 `module.*` 与 `*`；菜单、路由、按钮、接口四层校验。数据范围 `data_scope` 分全部、本部门、本人，在单据查询与服务端详情上生效。

**Q10：越权漏洞是怎么发现的？**
A：写了一个探针脚本，用"只有基础资料权限"的账号去读销售单据，结果返回 200；修复方式是让单据列表和详情按所属模块校验权限，并补了回归。这个例子在面试里很好用，因为它展示了主动找问题的能力。

**Q11：SQL 注入和 XSS 怎么防？**
A：所有 SQL 走参数化查询，探针里用 `' OR 1=1 --` 验证过；前端 React 默认转义，未使用 `dangerouslySetInnerHTML`。生产环境还需要加 CSP、HTTPS 与登录限流，这些在部署文档里列为上线前事项。

### 4.4 质量与工程化

**Q12：为什么既有 e2e 又要写探针？**
A：e2e 验证"正常路径能走通"，探针验证"异常路径走不通"（超发、超额核销、越权、非法金额），两者互补。探针用隔离数据库与独立端口，不会污染演示数据。

**Q13：交付后还发现过什么 bug？举一个。**
A：重复发货。两张发货单在订单未审核前都能拉到剩余数量，审核第一张后状态回写，但第二张审核时没有重新校验剩余量，导致超发。修复是在审核时按源单行重新计算可执行数量，超出就拒绝，并补了回归。

**Q14：如果流量涨 100 倍，瓶颈在哪，怎么改？**
A：瓶颈在单进程同步 SQLite 的写锁与 Node 单线程。改造路径：PostgreSQL 替换 SQLite、接口无状态化后可水平扩容、过账动作改为队列串行处理、报表走只读副本或预聚合。

**Q15：AI 辅助编码，你怎么保证质量？**
A：分三层：先定数据模型与接口契约，再让实现对齐契约；然后跑自动化验证；最后做边界攻击测试与代码审查。这次 9 个缺陷里有 8 个是探针发现的，说明"能跑"不等于"正确"，验证比生成更重要。

## 5. 演示脚本

### 5.1 60 秒版（投屏）

1. 工作台：说明 12 个月模拟数据与待办（10 秒）。
2. 销售订单：新建，选客户、仓库、物料，保存并提交、审核（20 秒）。
3. 从源单生成发货单：提交、审核（10 秒）。
4. 立刻打开库存余额、应收台账、会计凭证：三处同时出现新记录（15 秒）。
5. 财务报表：资产负债表显示平衡（5 秒）。

### 5.2 3 分钟版（技术面）

在 60 秒版基础上增加：

- 生产工单：领料、报完工，展示材料出库与成品入库凭证。
- 报表中心：经营驾驶舱与毛利分析。
- 权限对比：用 `guest/guest123` 登录，展示菜单与按钮差异。
- 架构一页：打开作品集网页的架构图，讲单据引擎与过账事务。

- [ ] `npm run seed` 重置演示数据
