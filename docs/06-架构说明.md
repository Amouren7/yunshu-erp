## 1. 系统概览

云枢ERP 是一套**单进程、单库、前后端同仓**的轻量 ERP：Node.js 内置 `node:sqlite` 持久化，原生 `node:http` 提供 REST API 并托管前端 SPA 静态资源，React 18 + Ant Design 5 渲染界面。没有 ORM、没有构建后端（Node 直接运行 `.mjs`），依赖只有 SQLite（内置）与前端 npm 包。

```
┌──────────────────────────── 浏览器（Chrome/Edge） ────────────────────────────┐
│  React 18 SPA（Vite 构建 → web/dist）                                          │
│   AppLayout（侧边菜单 / 标签页 / 全局搜索 / 通知）                              │
│   pages/**（按模块自动注册路由） + components/**（DataTable/DocEditor/…）        │
│   store（auth / meta） + api/client（fetch + Bearer token）                     │
└───────────────────────────────┬───────────────────────────────────────────────┘
                                │ HTTP JSON（同源，默认 127.0.0.1:8787）
┌───────────────────────────────▼───────────────────────────────────────────────┐
│  server/index.mjs（node:http）                                                 │
│   ① 静态资源：web/dist/* + SPA fallback（index.html）                          │
│   ② REST：自研极简 router → 鉴权 → 权限 → handler → 统一 JSON 信封              │
├───────────────────────────────────────────────────────────────────────────────┤
│  server/api/*.mjs（12 个模块，自动挂载）                                        │
│   auth / meta / documents / masterdata / inventory / dashboard                 │
│   finance / production / hr / crm / reports / system                           │
├───────────────────────────────────────────────────────────────────────────────┤

├───────────────────────────────────────────────────────────────────────────────┤
```

### 1.2 设计原则

1. **零外部服务**：一个 Node 进程 + 一个 SQLite 文件即可运行，便于演示与交付。
2. **元数据驱动**：单据字段、状态、动作、来源全部集中在 `lib/docTypes.mjs`，前端从 `/api/meta` 取配置渲染，**新增单据类型不需要写新表单页面**。
3. **过账即事实**：单据审核（`approve`）在事务内完成库存、发票、凭证的写入；已审核单据不可改。
4. **金额单点计算**：服务端 `lineCalc/docTotals` 是唯一金额口径，前端只做展示。
5. **只增不改的台账**：`stock_ledger`、`vouchers` 一旦写入不允许修改，冲销用反向记录。
6. **权限字符串化**：`模块.动作` + `*`/`模块.*` 通配，前后端同一套判断逻辑。

## 2. 运行时与请求处理

### 2.1 启动流程（`server/index.mjs`）

```
node server/index.mjs
  1) migrate()                      # 读 schema.sql，PRAGMA user_version < 1 时建表
  2) 遍历 server/api/*.mjs           # 动态 import，调用导出的 register(router)
  3) http.createServer(...)          # 监听 127.0.0.1:${ERP_PORT || 8787}
  4) 控制台打印 API 地址与数据文件路径
```

- 端口：环境变量 `ERP_PORT`，默认 **8787**；监听地址硬编码 `127.0.0.1`（仅本机可访问，部署到局域网需改这一行或前置反向代理）。
- 数据目录：`ERP_DATA_DIR`（默认 `server/data`），数据库文件名固定 `erp.db`。
- API 模块无需登记：新增 `server/api/xxx.mjs` 并导出 `register(router)` 即自动挂载（日志会打印 `[api] 已挂载 xxx.mjs`）。

### 2.2 请求管线

```
请求 → pathnameOf(req)
  ├─ 以 /api/ 开头 → router.match(method, pathname)
  │    ├─ 未匹配 → 404 {success:false, code:'NOT_FOUND'}
  │    ├─ authenticate(req)：Bearer token 或 ?token= → sessions 查库校验过期（默认 7 天）
  │    ├─ 非 public 且未登录 → 401 UNAUTHORIZED
  │    ├─ route.opts.perm 存在 → hasPermission(user, perm) → 403 FORBIDDEN
  │    ├─ POST/PUT/PATCH/DELETE → readBody(req)（上限 20 MB，JSON 解析）
  │    ├─ handler(ctx) 执行：ctx = { req,res,params,query,user,token,body,ip }
  │    └─ 返回值 → ok(res, data)；若返回 {__file} → 直接输出附件流
  └─ 其他路径 → web/dist 静态文件；命中则返回（/assets/* 长缓存）
       └─ 未命中 → SPA fallback 到 web/dist/index.html；无 dist 时返回"前端尚未构建"提示页
```

错误统一由 `ApiError(message, status, code)` 抛出，最外层 `fail(res, status, message, code)` 输出：
`{ "success": false, "message": "...", "code": "..." }`；成功输出 `{ "success": true, "data": ... }`。

## 4. 数据层

### 4.1 连接与约定

```js
// server/db.mjs（要点）
const db = new DatabaseSync(DB_FILE);
db.exec('PRAGMA journal_mode = WAL');
db.exec('PRAGMA foreign_keys = ON');
db.exec('PRAGMA busy_timeout = 5000');
```

- **同步 API**：`node:sqlite` 的 `DatabaseSync` 是同步接口，适合单进程轻量系统；并发写由 `busy_timeout` 兜底，**不要开多进程同时写**。
- **结果规整**：`normalize()` 把 `null-prototype` 行对象转为普通对象，`BigInt` 转 `Number`。
- **参数净化**：`safeParams()` 把 `undefined/NaN` 转为 `null`，布尔转 `0/1`（SQLite 不接受前两者）。
- **事务**：`tx(fn)` 用 `BEGIN IMMEDIATE … COMMIT/ROLLBACK` 包裹同步函数，过账路径必须使用。
- **迁移**：`migrate()` 读取 `PRAGMA user_version`，`< 1` 时整份执行 `schema.sql` 并置为 1；当前不区分增量迁移，升级 DDL 需自行补脚本。
- **种子判断**：`isSeeded()` 以 `users` 表是否有行判断（`/api/health` 暴露该状态）。

### 4.2 数据库文件

```
server/data/
├── erp.db        # 主库（SQLite 3）
├── erp.db-wal    # 预写日志（运行时存在）
└── erp.db-shm    # 共享内存索引（运行时存在）
```

备份/迁移必须**停服后三件一起复制**，或使用 `VACUUM INTO` 在线导出，详见 `07-部署与运维.md`。

## 5. 单据引擎（核心）

### 5.1 数据模型

```
documents（单据头，1）
  ├─ id, doc_no, doc_type, doc_date, status
  ├─ partner_type/partner_id/contact/phone/address      # 往来单位（多态：customer/supplier）
  ├─ salesperson_id, department_id, warehouse_id, to_warehouse_id
  ├─ currency, exchange_rate, payment_terms, due_date, project
  ├─ source_type, source_id, source_no                  # 转单来源（SO→DN、PO→GRN…）
  ├─ subtotal, discount_amount, tax_amount, total_amount, paid_amount, cost_amount
  ├─ extra_json                                         # 扩展字段（前端 x_ 前缀字段存这里）
  ├─ created_by/name/at, submitted_by/at, approved_by/at, closed_at, voided_at, print_count
  └── document_lines（单据行，N）
        ├─ item_id, item_code/name/spec/uom, qty, price, discount_rate, tax_rate
        ├─ amount, tax_amount, total_amount, cost, cost_amount
        ├─ warehouse_id, batch_no, production_date, expiry_date
        ├─ delivered_qty, invoiced_qty                  # 源单跟踪（父行已执行数量）
        ├─ source_line_id                               # 指向父单据行 id
        └─ extra_json                                   # 如 { invoice_id } 核销信息
document_logs（状态流转日志）
  └─ doc_id, action, from_status, to_status, user_id, user_name, remark, created_at
```

- 单据类型不建独立表，**12 种单据共用一套表结构**，由 `doc_type` 区分；差异字段通过 `extra_json`（前端 `x_` 前缀）承载。
- `document_lines.delivered_qty` 是父行已执行数量：子单据审核时 `+=`，父单据状态据此推进。
- `source_type/source_id/source_line_id` 构成可追溯的单据链，详情页"关联单据 + 操作日志"即据此展示。

### 5.2 单据注册表（`lib/docTypes.mjs`）

每种单据在 `DOC_TYPES` 中声明：

### 5.3 生命周期与状态机

```
创建(POST /api/documents)
  └─ DRAFT ──submit──▶ SUBMITTED ──approve──▶ APPROVED ──(业务推进)──▶ 完成/关闭
        │                   │                     │
        │ void              │ void                ├─ close（手工关闭）
        ▼                   ▼                     └─ void（作废，需按业务规则）
       VOID                VOID
```

- 状态变更唯一入口：`POST /api/documents/:id/action { action, remark }`；`transitionDocTo()` 校验"当前状态是否允许 + 是否具备 `${module}.${perm}` 权限"。
- `approve` 动作在**同一请求**中：更新状态字段 → 写 `document_logs` → 若 `t.effect` 存在则 `applyEffect()`（库存/发票/凭证）→ 回写来源行数量。
- 状态自动推进：`posting.mjs` 的 `refreshOrderStatus()` 依据子单据行数回写 SO/PO 的 `PARTIAL_SHIPPED / FULL_SHIPPED / PARTIAL_RECEIVED / FULL_RECEIVED`（详见第 6 节）。
- 编辑限制：只有 `DRAFT` 可 `PUT`；删除只允许 `DRAFT/VOID`。

### 5.4 转单（Pull）算法

`GET /api/documents/pull?sourceId=&docType=`（也可创建时只传 `sourceId`）：

```
读取源单据 + 其明细
对每个源行：remain_qty = qty − delivered_qty
目标单据行 = 源行剩余数量（默认全量，前端可改小）
写入时目标行 source_line_id = 源行 id
审核目标单据后：源行 delivered_qty += 本次数量，并重算源单状态
```

### 5.5 金额与税额口径

```
行未税金额 amount      = round2(qty × price × (1 − discount_rate/100))
行税额 tax_amount      = round2(amount × tax_rate/100)
行价税合计 total_amount = round2(amount + tax_amount)
表头 subtotal = Σ amount；tax_amount = Σ tax；total_amount = subtotal + tax
出库成本 cost_amount   = round2(qty × 出库时点 avg_cost)   # 由 stock.mjs 回填行 cost
```

### 5.6 元数据下发（前端驱动的关键）

`GET /api/meta` 一次性返回：`app`、`enums`（40 余个业务枚举）、`docTypes`（12 种单据的字段/状态/迁移/来源）、`modules`、`actions`、`dicts`（单位/币种/税率/物料分类/仓库/部门/科目）、`settings`。前端 `MetaProvider` 缓存它，`DocEditor`/`DocListPage` 完全按此渲染，**所以新增单据类型只改后端注册表**（前端还需加一条路由，见 §12）。

## 6. 过账与总账

### 6.1 过账效果表（`lib/posting.mjs`，真实实现）

| effect | 触发单据 | 库存动作 | 生成的凭证分录 |
|---|---|---|---|
| `SALES_DELIVERY` | DN | 按行 `stockOut`（移动加权平均） | 借 1122 应收账款（价税合计）/ 贷 6001 主营业务收入（未税）+ 贷 222101 销项税额；借 6401 主营业务成本 / 贷 1405 库存商品（成本额） |
| `SALES_RETURN` | SR | 按行 `stockIn`（原成本回库） | 借 6001 + 借 222101 / 贷 1122；借 1405 / 贷 6401（红字反向） |
| `PURCHASE_RECEIPT` | GRN | 按行 `stockIn`（采购单价） | 借 1403/1405 存货 + 借 222102 进项税额 / 贷 2202 应付账款 |
| `PURCHASE_RETURN` | PR | 按行 `stockOut`（当前均价） | 借 2202 / 贷 1405 存货 + 贷 222102 进项税额转出 |
| `TRANSFER` | TR | 调出仓 `stockOut` → 调入仓 `stockIn(成本平移)` | 不生成凭证 |
| `ADJUSTMENT` | ADJ | 按账面 vs 实盘差异 `stockIn/stockOut` | 盘盈：借 1405 / 贷 1901；盘亏：借 1901 / 贷 1405 |
| `OTHER_IN` | OI | `stockIn`（单价或标准成本） | 借 1403/1405 / 贷 1901 待处理财产损溢 |
| `OTHER_OUT` | OO | `stockOut` | 借 1901 / 贷 1403/1405 |
| `RECEIPT` | RC | — | 借 1001/1002（按结算方式）/ 贷 1122 应收账款；同时回写发票 `paid_amount`、生成 `payments` + `payment_allocations` |
| `PAYMENT` | PY | — | 借 2202 应付账款 / 贷 1001/1002；回写发票状态 |
| （独立函数）`postMaterialIssue` | 生产领料 | `stockOut` | 借 5001 生产成本 / 贷 1403/1405 |
| （独立函数）`postProductionCompletion` | 生产完工 | `stockIn` | 借 1405 库存商品 / 贷 5001 生产成本 |

- 同时回写来源单据行数量、刷新来源单据状态（`PARTIAL_*`/`FULL_*`）。
- 金额来源一律取单据字段，**不做反向推算**；凭证借贷不平会抛 `凭证借贷不平` 异常并回滚。
- 调拨不生成凭证，因为同一会计主体内部移动；跨主体调拨需开票（当前不支持）。

### 6.2 库存计价（`lib/stock.mjs`）

```
入库：(旧数量 × 旧均价 + 入库金额) / (旧数量 + 入库数量) = 新均价
出库：成本 = 当前均价；出库后数量减少、均价不变
每次变动写 stock_ledger：方向(IN/OUT)、数量、单位成本、金额、结存数量/成本
```

- `stock_balances(item_id, warehouse_id)` 为实时余额（qty / reserved_qty / avg_cost）。
- `stockOut` 当前**不校验负库存**（`settings.allow_negative_stock` 仅下发前端，未参与逻辑），属于已知限制，见 §13。
- 台账只增不改：冲销通过反向流水实现（作废红冲功能尚未完整实现）。

### 6.3 凭证（`lib/gl.mjs`）

- `vouchers`：`voucher_no`（格式 `记-YYYYMM-####`）、日期、期间、来源类型/来源 id、摘要、借贷合计、状态 `POSTED`。
- `voucher_lines`：科目编码、摘要、借/贷金额、往来对象、部门、来源行 id。
- `postVoucher()`：过滤零金额行 → 校验借贷平衡（容差 0.01）→ 取号 → 写主子表 → 返回凭证头。
- `accountBalances({startDate,endDate})`：按科目聚合凭证行借贷发生额，供余额表/报表使用。

## 7. 权限模型

### 7.1 模型

```
roles.permissions = JSON 字符串数组，元素形如：
  "*"                 → 全部权限（系统管理员）
  "sales.*"           → 销售模块全部动作
  "sales.approve"     → 单个动作
可选动作：view / create / edit / delete / submit / approve / export
另外 role.data_scope = all | dept | self（数据范围，已建模）
```

### 7.2 校验点

| 位置 | 行为 |
|---|---|
| 后端路由 | `router.get(path, handler, { perm: 'sales.view' })`；`index.mjs` 统一校验，未通过返回 403 |
| 后端逻辑 | `transitionDocTo()` 额外校验动作权限（`${module}.${perm}` 或 `${module}.edit` 兜底） |
| 前端菜单 | `AppLayout` 用 `hasPerm(route.perm)` 过滤菜单与路由 |
| 前端按钮 | `DocListPage/DocEditor/CrudPage` 用 `hasPerm` 控制新增/编辑/删除/动作按钮 |

- 未登录：除 `public: true` 的登录/登出接口外，一律 401。
- `data_scope` 目前**只存储与下发，未在查询层强制过滤**（列表接口未按部门/本人收敛），属已知限制。
- 会话：`sessions` 表 token（随机 24 字节 hex）+ 7 天过期；`authenticate()` 支持 `Authorization: Bearer` 与 `?token=`（用于下载/打印链接）。

## 9. 前端架构

### 9.1 入口与 Provider 链

```
web/index.html
  └─ src/main.tsx (React.StrictMode)
       └─ App.tsx
            ConfigProvider(zhCN, theme) → AntdApp → BrowserRouter
              → AuthProvider（token/用户/权限）

                 └─ RequireAuth → MetaProvider → AppLayout
                       └─ <Outlet> = 匹配到的路由页面（Suspense 懒加载兜底）
```

`AuthProvider`：token 存 `localStorage['erp_token']`；启动时 `GET /api/auth/me` 恢复用户；`hasPerm()` 支持 `*`/`模块.*`。

### 9.2 路由自动注册

## 11. 关键设计决策与不变量

| # | 决策 | 原因/约束 |
|---|---|---|
| 1 | 单据统一存 `documents`，不按类型建表 | 12 种单据共享状态机/权限/转单/日志，新增类型成本最低 |
| 2 | 状态机与字段元数据放 `docTypes.mjs`，前端从 `/api/meta` 取 | 单一事实来源，避免前后端两份定义漂移 |
| 3 | 审核时过账（approve 内做库存+凭证） | 业务与财务同步、事务内可回滚 |
| 4 | 移动加权平均成本 | 实现简单、可解释；FIFO/标准成本列为后续增强 |
| 5 | 金额服务端单点计算（`round2`） | 避免前后端各算一遍导致分位差 |
| 6 | 凭证与库存台账只增不改 | 可审计；冲销用反向记录 |
| 7 | `gl_mappings` 科目映射可配置 | 换账套/换科目只改映射，不改代码 |
| 8 | 前端路由自动发现（`import.meta.glob`） | 新增模块零侵入总路由 |
| 9 | 权限用字符串 `模块.动作` + 通配 | 简单可解释，种子角色已覆盖 8 类岗位 |
| 10 | 演示数据确定性生成（固定随机种子） | 每次 seed 汇总指标一致，便于截图/回归 |

**必须保持的不变量**：库存只能由单据过账变动；凭证借贷必平；金额一律两位小数；已审核单据不可编辑；状态只能经 `/action` 迁移。

## 13. 已知限制与演进方向

| 限制 | 影响 | 建议 |
|---|---|---|
| `data_scope` 未在查询层强制 | 部门/本人数据隔离仅停留在模型层 | 列表接口统一注入范围条件（按角色/部门） |

| 单元测试尚未建立 | `npm test` 实际执行 `scripts/e2e.mjs`（67 项端到端断言），无 `server/tests/` | 先以 e2e + audit + ui-flow 作为门禁；单测按 `04-模块落地清单.md` §7 补 |
| 凭证号按期间计数 | 并发下可能重号 | 加唯一索引或按序列取号 |
| 生产工单独立于单据引擎 | 工单走 `work_orders` 表 + `production.mjs` 专用接口，不进入 `documents` | 状态/领料/完工已闭环；若未来需要统一单据链（打印、审批流），再迁移为 documents 类型 |
| 完工成本为估算值（生产交接） | 完工入库单位成本 = 已领材料成本 × 1.18 ÷ 未完工数量；未领料时按标准成本 | 引入人工工时费率与制造费用分摊后替换系数 |
| BOM 权限走 `basedata.*`（生产交接） | 只有 `production.*` 的角色无法维护 BOM | 将 BOM 端点权限改为 `production.edit` 或在角色中同时授予 `basedata.*` |
| 报表驾驶舱部分图表依赖 `dashboard.view`（生产交接） | 仅 `reports.view` 时销售/采购/毛利趋势、品类占比、客户排行可能为空 | 报表接口内置 dashboard 聚合，或为报表角色追加 `dashboard.view` |
