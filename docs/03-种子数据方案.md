- 采样基线：**2026-10-23 12:00 对 `server/data/erp.db` 的只读实测**（不是估算）

## 0. 一句话结论

现有种子数据已经"能跑起来且有量"（700 张单据、1,820 张凭证、1,813 行库存流水、12 个月时间轴），但存在 **3 个结构性缺口**：
① 主数据太薄（物料 24 / 客户 22 / 供应商 12），撑不起"真实企业"的观感；
② **状态覆盖单极化**（已审核/已完成占 92%，几乎没有草稿、部分发货、部分入库、进行中工单、作废单），前端状态筛选、状态动作、异常流程全部看不到；
③ `document_logs` 为 **0 行**，"单据流转历史"页面必然是空白。
本方案给出：把数据量提升到 **M 档（约 1,500 张单据 / 260 张发票 / 3,000 张凭证）**、状态覆盖到 **每类单据 ≥6 种状态**、日志全量补齐的配方与校验 SQL，可增量改造 `seed.mjs`，不必推倒重来。

## 3. 演示叙事（数据要讲一个故事）

建议把种子企业设定为一家**工业传感器与采集网关制造商**（与现有 `settings.company_name=云枢科技（深圳）有限公司` 兼容）：

- **业务模式**：标准品备货 + 项目型定制；内销为主（CNY），少量外销（USD，汇率 7.15，用于多币种演示 P2）。
- **产品线**：① 传感器（温度/压力/流量，成品 SKU 约 30）② 采集网关（含 PCBA 半成品）③ 配件与线束 ④ 技术服务（按次计费）。
- **供应链**：原料来自 20 家供应商（其中 4 家外协加工），成品发往 6 个区域（华南/华东/华北/华中/西南/出口）。
- **组织**：11 个部门（总经办/销售/采购/生产/仓储/品质/财务/人力/研发/售后/IT），45 名员工，8 个角色（管理员/销售/采购/仓管/生产/财务/HR/只读）。

## 4. 分域数据配方

### 4.1 销售域

```
客户 60 家：
  A 级（10 家，信用额度 50~200 万，账期 60/90 天）
  B 级（30 家，额度 10~50 万，账期 30 天）
  C 级（20 家，额度 3~10 万，现款/预付 30%）

SO 260 张（2025-11 ~ 2026-10，月均 ~22 张）：
  DRAFT 8       → 演示"提交"动作
  SUBMITTED 12  → 演示"审核"
  APPROVED 25   → 演示"转发货单"
  PARTIAL_SHIPPED 35   → 演示"继续发货/关闭"
  FULL_SHIPPED 120     → 正常完成
  COMPLETED 40         → 已开票已收款
  CLOSED 12            → 提前关闭
  VOID 8               → 演示作废（无下游）
DN 230 张：DRAFT 6 / SUBMITTED 8 / APPROVED 200 / VOID 16
SR 15 张：APPROVED 12 / DRAFT 1 / SUBMITTED 2
```

规则：

- **每张 SO 的行数 1~8 行**，金额跨度 3,000 ~ 800,000 元（对数分布，避免全是同一量级）；
- `PARTIAL_SHIPPED` 的 SO 必须真实存在"已发 40%~80% 的 DN + 对应 AR 发票"；
- `FULL_SHIPPED` 的 SO 必须有足额 DN；`COMPLETED` 的必须有足额收款；
- 应收账款账龄要人为分布：未收 25%（其中 30/60/90/90+ 各占约 25%）、部分收 10%、已收 65%；

## 6. 一致性不变量与自动修复

种子脚本生成完必须跑一遍"断言 → 修复 → 再断言"（幂等）：

| # | 不变量 | 断言 SQL 要点 | 失败时 |
|---|---|---|---|
| I1 | 无负库存 | `SELECT COUNT(*) FROM stock_balances WHERE qty < -0.001` = 0 | 中止并打印物料/仓库 |
| I2 | 余额 = 台账最后结存 | 对每个 `(item, warehouse)` 取 `stock_ledger` 最后 `balance_qty`，与 `stock_balances.qty` 比对 | 重算余额 |
| I3 | 单据日志齐全 | 每张 `APPROVED` 单据 `document_logs ≥ 2` | 补写日志 |
| I4 | 母单行数量守恒 | `SUM(子行.qty)` ≤ `父行.qty`；父行 `delivered_qty = SUM(子行.qty)` | 重算回写 |
| I5 | 发票余额 = 总额 − 已付 | `paid_amount ≤ total_amount`；`status` 与差额一致 | 重算状态 |
| I6 | 收款核销 ≤ 收款金额 | `SUM(payment_allocations.amount) ≤ payments.amount` | 截断/拆分 |
| I7 | 借贷平衡 | `ABS(total_debit-total_credit) ≤ 0.01` | 中止 |
| I8 | 收入/成本匹配 | `|6001 贷方 − ΣDN.subtotal| ≤ 1`、`|6401 借方 − ΣDN.cost_amount| ≤ 1` | 查 effect 缺失 |
| I9 | 库存金额与总账 | `|Σ(qty×avg_cost) − (1403+1405 余额)| ≤ 1` | 打印差异 |
| I10 | 每张已审核单据有凭证 | `GL_DOC_TYPES` 中每张 APPROVED 单据在 `vouchers(source_type,source_id)` 有记录 | 补过账 |

> 现有 `scripts/check.mjs` 已覆盖 I1/I7 与若干汇总项，建议把 I2~I6、I8~I10 加进去，变成 `npm run seed && npm run check` 一条命令的准入门槛。

| `/api/dashboard/recent-docs` | 有值 | 最近 20 条覆盖 6 种单据类型 |

报表验收口径（跑 `check.mjs` 之外再补）：

- 资产负债表：`资产合计 = 负债合计 + 所有者权益合计`（差异 ≤ 1 元）；
- 利润表：`营业收入 − 营业成本 − 期间费用 = 营业利润`，且**利润为正**（否则演示"亏损企业"观感差）；
- 毛利率：整体 **15%~35%**；分产品成本率 60%~75%；
- 库存周转：年化 **3~6 次**；库存金额占月均销售成本的 2~4 个月；
- 应收账龄：90+ 占比 **10%~20%**（太低显得风控完美，太高显得经营恶化）。

## 8. 校验 SQL 清单（可直接拷到 `scripts/check.mjs`）

```sql
-- 01 状态覆盖：SO 每个状态至少 5 条
SELECT status, COUNT(*) c FROM documents WHERE doc_type='SO' GROUP BY status HAVING c < 5;

-- 02 工单状态覆盖
SELECT status, COUNT(*) c FROM work_orders GROUP BY status;

-- 03 单据日志覆盖率（应为 0）
SELECT COUNT(*) c FROM documents d
WHERE d.status <> 'DRAFT'
  AND (SELECT COUNT(*) FROM document_logs l WHERE l.doc_id = d.id) < 2;

-- 04 负库存（应为 0）
SELECT COUNT(*) c FROM stock_balances WHERE qty < -0.001;

-- 05 母单数量守恒（应为 0）
SELECT COUNT(*) c FROM document_lines l JOIN documents d ON d.id = l.doc_id
WHERE d.doc_type='SO' AND l.delivered_qty > l.qty + 0.001;

-- 06 发票状态与金额一致（应为 0）
SELECT COUNT(*) c FROM invoices
WHERE paid_amount > total_amount + 0.01
   OR (status IN ('已收','已付') AND ABS(paid_amount-total_amount) > 0.01);

-- 07 借贷不平（应为 0）
SELECT COUNT(*) c FROM vouchers WHERE ABS(total_debit-total_credit) > 0.01;

-- 08 收入与销售对账（差异应 <= 1）
SELECT ROUND((SELECT SUM(subtotal) FROM documents WHERE doc_type='DN' AND status<>'VOID'),2) AS doc_revenue,
       ROUND((SELECT SUM(vl.credit-vl.debit) FROM voucher_lines vl JOIN accounts a ON a.code=vl.account_code
              WHERE a.code='6001'),2) AS gl_revenue;

-- 09 库存金额与总账对账
SELECT ROUND((SELECT SUM(qty*avg_cost) FROM stock_balances),2) AS stock_amt,
       ROUND((SELECT SUM(vl.debit-vl.credit) FROM voucher_lines vl
              WHERE vl.account_code IN ('1403','1405')),2) AS gl_amt;

-- 10 应付/应收余额与发票对账
SELECT ROUND((SELECT SUM(total_amount-paid_amount) FROM invoices WHERE invoice_type='AR' AND status<>'已作废'),2) AS ar_open,
       ROUND((SELECT SUM(credit-debit) FROM voucher_lines WHERE account_code='1122'),2) AS gl_ar;

-- 11 每月单据量（趋势图空月）
SELECT substr(doc_date,1,7) m, COUNT(*) c FROM documents GROUP BY m ORDER BY m;

-- 12 客户销售集中度（Top10 占比）
SELECT ROUND(SUM(CASE WHEN rn<=10 THEN amt ELSE 0 END)/SUM(amt)*100,1) pct FROM (
  SELECT partner_id, SUM(total_amount) amt, ROW_NUMBER() OVER (ORDER BY SUM(total_amount) DESC) rn
  FROM documents WHERE doc_type='DN' AND status<>'VOID' GROUP BY partner_id);
```
