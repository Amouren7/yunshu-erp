## 0. 阅读方式

本文所有流程都以**单据链**为单位描述，每张单据必须回答四个问题：

1. **从哪来**：`source_type / source_id / source_no`（转单来源；无来源则手工创建）
2. **能到哪**：可生成哪些下游单据（发货、入库、发票、收付款、领料、完工）
3. **何时生效**：哪个状态变化触发库存/财务效果（本系统统一为 **审批通过 APPROVED 时过账**）
4. **怎么记账**：借什么、贷什么、金额取哪一列

> 系统不变量（任何新功能都必须满足）：
> - **I1** 库存余额只能通过 `stockIn/stockOut` 变动，且必须同时写 `stock_ledger`（只增不改）。
> - **I2** 凭证只能由 `postVoucher` 写入，借贷必平，且同一 `source_type+source_id` 只能生成一次（幂等）。
> - **I3** 已 `APPROVED` 的单据不可编辑，只能作废（VOID）或红冲；作废/红冲必须写 `document_logs`。
> - **I4** 子单据数量回写父单据行：`document_lines.delivered_qty / invoiced_qty`，父单据据此推进状态。
> - **I5** 所有金额 `round2`（两位小数、四舍五入），税额按行计算后汇总，禁止"总额倒挤明细"。

## 1. 通用单据引擎约定

### 1.1 单据主状态机（现有 `BASE_STATUS` + 各类型扩展）

```
                 ┌──────────── submit ────────────┐
                 │                                ▼
   ┌─────────┐   │   ┌──────────────┐   approve   ┌──────────┐
   │  DRAFT  │───┴──▶│  SUBMITTED   │────────────▶│ APPROVED │
   │  草稿    │       │   待审批      │             │  已审核   │
   └─────────┘       └──────────────┘             └────┬─────┘
        │                    │                        │
        │ void               │ void                   ├──▶ 业务子状态（部分发货/部分入库/…）
        ▼                    ▼                        │
   ┌─────────┐          ┌─────────┐                   ├──▶ CLOSED（关闭，不再执行）
   │  VOID   │          │  VOID   │                   └──▶ VOID（作废，已审核单据需先红冲）
   │ 已作废   │          │ 已作废   │
   └─────────┘          └─────────┘
```

- 动作表由 `docTypes.mjs` 的 `transitions` 驱动：`{ action, label, from[], to, perm, confirm }`。
- 前端只渲染 `availableActions()` 返回的动作；后端必须**再校验一次**（防止绕过 UI）。
- 每次状态变化写 `document_logs(doc_id, action, from_status, to_status, user_id, user_name, remark)`。

### 1.2 转单与数量回写（所有域统一）

```
父单据行(document_lines)                       子单据行(document_lines)
  source_line_id ──────────────────────────────▶ source_line_id
  qty = 100                                     qty = 60（本次）
  delivered_qty = 0 ──过账时 += 60──────────────▶ 回写
                                                  ↓
                       父单据状态重算：0 < 60 < 100 → PARTIAL_*
                       再发 40 → delivered_qty = 100 → FULL_*
```

- 子单据保存时只校验"本次数量 ≤ 父行剩余数量（qty − delivered_qty）"，**不立即扣减**；
- 子单据审批通过时执行"回写 + 库存/凭证效果"，同一事务内完成（SQLite `BEGIN/COMMIT`）。

### 1.3 过账时机与幂等

| 单据 | 审批时的效果 | 是否生成凭证 | 现有实现 |
|---|---|---|---|
| `SO` 销售订单 | 无库存/凭证效果，仅锁定价格与信用 | 否 | `effect: null` |
| `DN` 销售发货单 | 出库（`stockOut`）+ 生成 AR 发票 + 凭证 | 是 | `effectSalesDelivery` |
| `SR` 销售退货单 | 入库（按原成本）+ 冲减 AR + 红字凭证 | 是 | `effectSalesReturn` |
| `PO` 采购订单 | 无效果 | 否 | `effect: null` |
| `GRN` 采购入库单 | 入库（`stockIn`）+ 生成 AP 发票 + 凭证 | 是 | `effectPurchaseReceipt` |
| `PR` 采购退货单 | 出库（按当前均价）+ 冲减 AP + 红字凭证 | 是 | `effectPurchaseReturn` |
| `TR` 库存调拨单 | 出库仓 `stockOut` + 调入仓 `stockIn`（成本平移） | 否（同一法人内部调拨） | `effectTransfer` |
| `ADJ` 库存盘点单 | 差异调整库存 | 是（盘盈/盘亏） | `effectAdjustment` |
| `OI/OO` 其他出入库 | 入库/出库 | 是 | `effectOtherIn/Out` |
| `RC` 收款单 | 核销 AR 发票 + 凭证 | 是 | `effectReceipt` |
| `PY` 付款单 | 核销 AP 发票 + 凭证 | 是 | `effectPayment` |
| `WO` 生产工单（P0 扩展） | 领料出库 / 完工入库 / 成本归集 | 是 | 待实现 |

幂等实现建议：`vouchers(source_type, source_id)` 唯一索引；`stock_ledger(doc_type, doc_id, item_id, warehouse_id, direction)` 唯一索引，重复过账直接报错。

## 2. 销售到收款（O2C：Order to Cash）

### 2.1 端到端单据流

```
[1] 商机/合同                 [2] 报价单 QUO            [3] 销售订单 SO
  CRM.opportunities  ─────▶   QUO（P1，可跳过）  ─────▶  SO
                                                            │ 审批：APPROVED
                                                            │ 校验：客户信用额度、价格、库存可承诺量
                                                            ▼
[4] 销售发货单 DN  ◀────────────── 按行转单（部分/全部）────────────────┘
      │ 审批 → 出库 stockOut(1405→成本6401) + 生成 AR 发票 + 凭证
      │ 回写 SO.delivered_qty → SO 状态 PARTIAL_SHIPPED / FULL_SHIPPED
      ▼
[5] 应收发票（invoices, invoice_type=AR）   ← 由 DN 自动生成（P0）；P1 支持先开票后发货
      │ 到期日 = 单据日期 + 客户 credit_days（或付款条件）
      │ 状态：未收 → 部分收款 → 已收 / 已核销
      ▼
[6] 收款单 RC  ── 核销 ──▶ 更新发票 paid_amount / status
      │ 审批 → 借 1001/1002，贷 1122
      │ 未核销余额 → 预收（贷 2203）
      ▼
[7] 账龄报表 / 客户对账单 / 回款分析
```

### 2.2 销售订单状态机（现行枚举，务必冻结）

```
DRAFT ──submit──▶ SUBMITTED ──approve──▶ APPROVED
  │                    │                     │
  │ void               │ void                ├─ 首次部分发货 ──▶ PARTIAL_SHIPPED
  ▼                    ▼                     ├─ 发货齐套 ─────▶ FULL_SHIPPED
VOID                 VOID                    ├─ 开票完成(收齐款) ─▶ COMPLETED
                                             ├─ 手工关闭 ─────▶ CLOSED
                                             └─ 作废 ─────────▶ VOID（需先红冲下游）
```

- `PARTIAL_SHIPPED` / `FULL_SHIPPED` 由 DN 过账后**自动**推进，不允许手工设置；
- `COMPLETED` 建议条件：`delivered_ratio = 100%` 且 `billed_ratio = 100%`（P1 增加比率字段后自动判定）；
- `CLOSED` 用于"剩余不再发货/开票"的提前收口，必须有权限 + 备注。

### 2.3 O2C 会计分录（每步一张凭证，按现有 `posting.mjs` 口径）

| 步骤 | 触发单据 | 借方 | 贷方 | 金额来源 | 实现状态 |
|---|---|---|---|---|---|
| 发货并确认收入 | DN 审批 | `1122 应收账款` | `6001 主营业务收入`（未税） | `documents.total_amount` / `subtotal` | ✅ 已实现 |
| 销项税额 | DN 审批 | — | `2221.01 应交税费-应交增值税(销项税额)` | `documents.tax_amount` | ✅ 已实现 |
| 结转成本 | DN 审批 | `6401 主营业务成本` | `1405 库存商品`（原料经 1403） | 行 `cost_amount` 汇总 | ✅ 已实现 |
| 销售退货 | SR 审批 | `6001`（红字）/ `2221.01`（红字）/ `1405` | `1122` / `6401` | 同发货反向 | ✅ 已实现 |
| 收款 | RC 审批 | `1001 库存现金` 或 `1002 银行存款` | `1122 应收账款` | `payments.amount` | ✅ 已实现 |
| 预收（未核销） | RC 审批 | `1001/1002` | `2203 预收账款` | 未核销金额 | ⬜ 待补（P1） |
| 坏账核销 | 手工凭证 | `6602/6701`（扩展） | `1122` | 核销金额 | ⬜ 待补（P2） |

> 收入确认时点：本系统采用**发货确认收入**（ERPNext Delivery Note 口径）。若要求"开票确认收入"，只需把上述前三条凭证迁移到发票审批环节，`posting.mjs` 抽一个 `postSalesInvoice()` 即可，不要两处都记。

## 3. 采购到付款（P2P：Procure to Pay）

### 3.1 端到端单据流

```
[1] 采购申请 PRQ（P1）        [2] 询价/报价 RFQ（P1）       [3] 采购订单 PO
  部门/库存缺口  ──────────▶   多供应商比价  ─────────────▶  PO
                                                              │ 审批 APPROVED
                                                              │ 校验：供应商账期、价格、预算（P2）
                                                              ▼
[4] 采购入库单 GRN ◀──────── 按行转单（支持部分到货）───────────┘
      │ 审批 → 入库 stockIn（1403/1405，按价税分离）
      │ 回写 PO.delivered_qty → PO 状态 PARTIAL_RECEIVED / FULL_RECEIVED
      ▼
[5] 应付发票（invoices, invoice_type=AP）  ← GRN 自动生成；供应商发票号登记
      │ 到期日 = 入库日 + 供应商 credit_days
      │ 三单匹配：PO 单价/数量 ↔ GRN 实收 ↔ AP 发票
      ▼
[6] 付款单 PY ── 核销 ──▶ 更新发票 paid_amount / status
      │ 审批 → 借 2202，贷 1002
      ▼
[7] 应付账龄 / 供应商对账 / 采购价格分析
```

### 3.2 采购订单状态机（现行）

```
DRAFT ──submit──▶ SUBMITTED ──approve──▶ APPROVED
  │                    │                     │
  │ void               │ void                ├─ 首次部分到货 ──▶ PARTIAL_RECEIVED
  ▼                    ▼                     ├─ 到货齐套 ─────▶ FULL_RECEIVED
VOID                 VOID                    ├─ 全部开票核对完成 ─▶ COMPLETED
                                             ├─ 手工关闭 ─────▶ CLOSED
                                             └─ 作废 ─────────▶ VOID
```

### 3.3 P2P 会计分录

| 步骤 | 触发单据 | 借方 | 贷方 | 说明 | 实现状态 |
|---|---|---|---|---|---|
| 采购入库（票货同行） | GRN 审批 | `1403 原材料` / `1405 库存商品` + `2221.01 应交税费-应交增值税(进项税额)` | `2202 应付账款` | 按物料类型选存货科目（`inventoryAccount()`） | ✅ 已实现 |
| 采购退货 | PR 审批 | `2202` | `1403/1405` + `2221.01（进项税额转出）` | 红字 | ✅ 已实现 |
| 暂估入库（货到票未到） | 月末手工 | `1403/1405` | `2202 应付账款-暂估` | 次月红冲，发票到后正式入账 | ⬜ P1 |
| 付款 | PY 审批 | `2202 应付账款` | `1002 银行存款` | 核销 AP | ✅ 已实现 |
| 预付（未核销） | PY 审批 | `1123 预付账款` | `1002` | 后续到票冲抵 | ⬜ P1 |
| 采购费用（运费/关税） | 手工或费用单 | `1403/1405`（摊入成本）或 `6601` | `2202/1002` | 到岸成本分摊 | ⬜ P2 |

> 三单匹配规则（P0 必须至少有校验，P1 做成页面）：
> `GRN行.qty ≤ PO行.qty − PO行.delivered_qty`；`AP发票行.qty ≤ GRN行.qty`；`AP单价与PO单价差异 > 1%` 时禁止自动过账，转人工确认。

## 4. 计划到生产（Plan to Produce）

### 4.1 端到端单据流

```
[1] 需求来源                         [2] 生产计划（P1）              [3] 生产工单 WO
  销售订单 SO / 销售预测 / 安全库存 ──▶ 生产计划 PP ───────────────▶ WO
                                        （按交期倒排、按 BOM 展开）      │ RELEASED
                                                                        │ 校验：BOM 完整性、物料齐套
                                                                        ▼
[4] 领料单（材料出库）  ◀── 按 BOM × 工单数量（含损耗率）生成 ──────────┘
      │ 审批 → stockOut(1403 → 5001 生产成本-直接材料)
      ▼
[5] 工序报工（P1）── 工序 1..n：开始/结束/完成数/不良数/工时
      │ 人工成本：借 5001-直接人工，贷 2211 应付职工薪酬
      ▼
[6] 制造费用归集（月末）  5101 制造费用 → 分摊 → 借 5001，贷 5101
      ▼
[7] 完工入库单 FG ◀── 成品入库（1405）+ 成本结转（5001 → 1405）
      │ 单位成本 = 工单归集总成本 / 完工数量
      ▼
[8] 成本分析：材料/人工/制造费用占比，标准成本 vs 实际（P2）
```

### 4.2 工单状态机（建议冻结，与现有 `work_orders.status` 默认值一致）

```
DRAFT ──release──▶ RELEASED ──start──▶ IN_PROGRESS ──finish──▶ COMPLETED ──close──▶ CLOSED
  │                   │                    │                      │
  │ void              │ void               │ void                 │ void
  ▼                   ▼                    ▼                      ▼
VOID                VOID                 VOID                    VOID
```

- `RELEASED`：BOM 已锁定、领料需求已生成、可开始领料；
- `IN_PROGRESS`：首次领料或首次报工后自动置位；
- `COMPLETED`：完工入库数量 ≥ 计划数量（允许超入/短入，短入需 `close` 确认）；
- `CLOSED`：财务成本已结平，不再允许修改。

### 4.3 生产相关分录

| 事件 | 借方 | 贷方 | 说明 |
|---|---|---|---|
| 生产领料 | `5001 生产成本-直接材料` | `1403 原材料` | 按 BOM 定额 × 实际单价（移动加权平均） |
| 直接人工 | `5001 生产成本-直接人工` | `2211 应付职工薪酬` | 报工工时 × 小时工资率 |
| 制造费用归集 | `5101 制造费用` | `1002/1001/2211/1602`（折旧） | 水电、折旧、车间管理工资 |
| 制造费用结转 | `5001 生产成本-制造费用` | `5101 制造费用` | 按工时/机时/产量分摊 |
| 完工入库 | `1405 库存商品` | `5001 生产成本` | 单位成本 = 归集总成本 ÷ 完工数 |
| 废品损失 | `5001` 或 `6711 营业外支出`（扩展） | `1403/1405` | 责任赔偿冲减 |

## 5. 库存流转（Inventory Flow）

### 5.1 全部库存变动来源（穷举，禁止第 13 种）

| # | 单据 | 方向 | 成本 | 是否生成凭证 | 现有 |
|---|---|---|---|---|---|
| 1 | `DN` 销售发货 | 出 | 移动加权平均（出库时点） | 是 | ✅ |
| 2 | `SR` 销售退货 | 入 | 按原发货行成本（`document_lines.cost`） | 是 | ✅ |
| 3 | `GRN` 采购入库 | 入 | 采购价（未税单价） | 是 | ✅ |
| 4 | `PR` 采购退货 | 出 | 当前移动加权平均 | 是 | ✅ |
| 5 | `TR` 调拨 | 出+入 | 出库仓成本 → 调入仓同额 | 否 | ✅ |
| 6 | `ADJ` 盘点 | 双向 | 当前均价 | 是 | ✅ |
| 7 | `OI` 其他入库 | 入 | 指定成本或当前均价 | 是 | ✅ |
| 8 | `OO` 其他出库 | 出 | 当前均价 | 是 | ✅ |
| 9 | `WO` 生产领料 | 出 | 当前均价 → `5001` | 是 | ⬜ 待做 |
| 10 | `FG` 完工入库 | 入 | 工单归集成本 | 是 | ⬜ 待做 |
| 11 | 组装/拆卸（P2） | 双向 | BOM 成本 | 是 | ⬜ |
| 12 | 期初导入 | 入 | 指定成本 | 是（期初凭证） | ⬜ P1 |

### 5.2 调拨与盘点流程

```
调拨 TR：调出仓 A ──stockOut──▶ 库存流水(OUT) ──成本 X ──▶ 调入仓 B stockIn(unitCost=X)
         不产生凭证（同一会计主体内部移动）；跨主体调拨才需要开票

盘点 ADJ：账面数量(Q1) vs 实盘数量(Q2)
          Q2 > Q1 → 盘盈：stockIn(差额)，借 1405/1403，贷 1901 待处理财产损溢
          Q2 < Q1 → 盘亏：stockOut(差额)，借 1901，贷 1405/1403
          审批处理后：盘盈冲减管理费用（贷 6602 红字），盘亏按责任转 6602/6711
```

### 5.3 库存状态与可用量口径

```
可用量 available = stock_balances.qty − stock_balances.reserved_qty − 在途占用
可承诺量 ATP  = 可用量 + 在途采购（已审批未入库）− 已接订单未发货
```

- P0：`available = qty − reserved_qty`，`reserved_qty` 在订单审核时累加、发货时释放；
- P1：引入 ATP（需要采购在途与销售未发数量聚合），仪表盘展示"可承诺库存"。

## 8. 红冲、反审核、反结账规则

```
正常路径：DRAFT → SUBMITTED → APPROVED（过账，库存+凭证）
                                     │
错误发现 ──┬── 当天未记账：允许 APPROVED → VOID（反向释放库存 + 红冲凭证）
           ├── 已跨期：必须生成"红字单据"（SR/PR 或手工红字凭证），原单标记 CLOSED
           └── 已结账：只能在下期做红字，禁止反结账改历史（P2 才提供反结账，需二次确认+审计日志）
```

- 红冲凭证规则：借贷方向互换、金额相同、摘要带"红冲：{原单号}"、`source_type` 加 `_REVERSAL` 后缀或 `reversal_of` 字段；
- 库存红冲：生成反向 `stock_ledger` 行，`qty_in/qty_out` 互换，**不删除原流水**；
- 已开票已收款的单据作废，必须先作废收款/发票，顺序不能乱（按依赖倒序）。

## 9. 对账口径（财务与业务必须能对上）

| 对账项 | 业务口径 | 财务口径 | 差异处理 |
|---|---|---|---|
| 存货金额 | `SUM(stock_balances.qty × avg_cost)` | `1403 + 1405` 科目余额 | 差异 > 0.01 报警（通常是遗漏过账或手工调账） |
| 应收账款 | `SUM(AR 发票 total − paid)` | `1122` 科目余额 | 含未开票应收时需加"已发货未开票" |
| 应付账款 | `SUM(AP 发票 total − paid)` | `2202` 科目余额 | 含暂估应付 |
| 销售收入 | `SUM(DN.subtotal)` | `6001` 贷方发生额 | 退货单需冲减 |
| 销售成本 | `SUM(DN.cost_amount)` | `6401` 借方发生额 | 同上 |
| 库存数量 | `stock_balances.qty` | 无（数量账） | 与 `stock_ledger` 累计一致 |

> 建议在"系统管理 → 数据健康"页面固化这 6 个对账查询（P1），每次结账前必须全部为 0 差异。
